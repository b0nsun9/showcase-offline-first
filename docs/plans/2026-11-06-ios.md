# iOS Offline-First Field-Job App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the iOS app in which a field worker completes today's jobs, each with a photo and an optional note. Every completion is final on the phone straight away, and is sent once to the hosted API when the signal allows.

**Architecture:** Clean Architecture in three parts:

- **Domain:** a Swift package with entities, the `JobRepository` protocol, the use cases and the merge rule. It imports only Foundation.
- **Data:** a Swift package with the Core Data store, the API client, the send queue and `LiveJobRepository`. It depends on Domain.
- **The app target:** SwiftUI views, `ObservableObject` view models and the composition root.

The calls go view → view model → use case → `JobRepository` ← Data.

**Tech Stack:** Swift 6.4 (Xcode 27.2), SwiftUI, Core Data, URLSession, Network (`NWPathMonitor`), CryptoKit, UIKit (`UIImagePickerController`) and Swift Testing. No third-party libraries.

**Spec:** `docs/specs/2026-11-06-ios-offline-first-app.md`

## Global Constraints

- **Versions.**
  - The app and both packages have a minimum of iOS 15.6.
  - Test targets need a minimum of iOS 17.0, because Xcode 27.2's Swift Testing is built for `ios17.0-simulator`.
  - The packages also declare `.macOS(.v14)`, so their tests run on the Mac with `swift test`. Swift Testing on macOS is built for `macos14.0`.
- **Platform APIs.**
  - No `@Observable`, `NavigationStack`, `PhotosPicker`, `Clock` or `Duration`, since those need iOS 16 or 17.
  - Use `ObservableObject` and `@Published`, `NavigationView`, `Task.sleep(nanoseconds:)` and `Date`.
- **No third-party dependencies**, in the app or the tools.
- **No third-party project tools.** That means no Tuist, XcodeGen, CocoaPods or Carthage. `ios/FieldJobs.xcodeproj` is created from Xcode's own App template through Xcode's MCP server, and is maintained in Xcode or by hand. Code is shared only through local Swift packages. Nothing in the build, the tests or CI installs Homebrew or `mise` tools.
- **Domain imports only `Foundation`** and never mentions `URLSession`.
  - `ios/scripts/check-domain-imports.sh` enforces this, both in CI and locally.
  - This is the real enforcement. A Swift package can always import system frameworks, so being a separate package alone doesn't stop it.
- **API hosts.**
  - Debug builds use `dev.api.showcase.bonsung.me`. Release builds use `api.showcase.bonsung.me`.
  - Integration tests and CI use dev.
- **Headers.** Every `/v1` request carries:
  - `Authorization: Bearer <key>`
  - `X-Install-Id: <uuid>`
  - `Idempotency-Key: <uuid>` on `POST /v1/jobs/{id}/complete` only
- **Limits.**
  - A note may be at most 1000 UTF-16 code units (`note.utf16.count <= 1000`).
  - A photo may be at most 5,242,880 bytes, sent with `Content-Type: image/jpeg`.
- **Completion body.** Exactly `{"completedAt":"<ISO 8601 UTC with milliseconds, e.g. 2026-11-06T08:42:00.000Z>","note":<string or null>}`. It's stored at Complete time and resent byte-for-byte on every retry.
- **Timeouts.** 30 seconds per request, 60 seconds for a photo upload.
- **Backoff.**
  - The wait is `min(2 × 2^(attempt−1), 300)` seconds, times a jitter factor in `0.8...1.2`.
  - Backoff waits reset when the network comes back.
  - A 409 waits `Retry-After` seconds, and a 429 pauses **all** writes for `Retry-After` seconds.
- **Secrets.**
  - The API key lives only in `ios/Secrets.xcconfig`, which git ignores, as `API_KEY_DEV` and `API_KEY_PROD`.
  - Nothing logs request headers or the key. The app has no request logging at all.
  - CI reads the dev key from the secret `SHOWCASE_DEV_API_KEY`, as an environment variable of the same name, and never echoes it.
- **Install ID.** A UUID kept in `UserDefaults` under the key `installID`.
- **On-screen copy** is pinned by the view-model tests in Tasks 5 and 6, and is in English.
- **Workflow, from `AGENTS.md`.**
  - Tests come before code.
  - Each task gets its own branch, `ios/task-<N>-<slug>`. The branch starts from `develop`, or from the previous task's branch if that hasn't been merged yet.
  - The pull request goes up to `develop` only after the stage 4 tests and review and the stage 5 compound step.
  - Only the owner merges, and nobody force-pushes.

## Review Focus

- **A draft survives a refresh.** A to-do job already has a draft photo or note, and a refresh reports the job as pending. The draft must survive (Task 1: `mergeKeepsDraftOfPendingJob`).
- **Emoji notes.** 500 × "👍" is 1000 UTF-16 units and is allowed; 501 is rejected. The counter shows UTF-16 units (Task 1: `noteLimitCountsUTF16`; Task 6: `counterCountsUTF16`).
- **A double tap on Complete** records one completion with one key (Task 3: `completingTwiceThrowsAlreadyCompleted`; Task 6: `completeIsDisabledWhileCompleting`).
- **Two send triggers at once.** If the network returns while a foreground drain is running, no item is sent twice in parallel (Task 4: `concurrentSendPendingSendsEachItemOnce`).
- **The app killed mid-send.** If the app is killed after a completion has gone out but before its answer arrives, a relaunch still finds the same key and body queued (Task 3: `queuedCompletionSurvivesReopeningStore`; Task 4: `retryAfterDroppedAnswerReusesKeyAndBody`).

    public var photo: PhotoInfo?        // set once a photo exists, draft or confirmed

    public static let noteLimit = 1000          // UTF-16 code units
    public static let photoByteLimit = 5_242_880
}
public struct PhotoInfo: Equatable, Sendable { public let bytes: Int; public let sha256: String }
public enum SyncState: Equatable, Sendable { case notCompleted, waiting, sent, couldNotSend }
public struct JobsSnapshot: Equatable, Sendable {
    public var jobs: [Job]; public var updatedAt: Date?; public var isOnline: Bool; public var sendingBlocked: Bool
}
public enum JobError: Error, Equatable { case unknownJob, photoMissing, photoAlreadyTaken, photoTooLarge, noteTooLong, alreadyCompleted }

public protocol JobRepository: Sendable {
    func snapshots() -> AsyncStream<JobsSnapshot>      // yields the current state at once, then after every change
    func refresh() async throws
    func job(id: String) async throws -> Job?
    func photoData(jobID: String) async throws -> Data?
    func savePhoto(jobID: String, jpeg: Data) async throws
    func saveNote(jobID: String, note: String?) async throws
    func complete(jobID: String, completedAt: Date) async throws   // one atomic save, see Task 3
    func sendPending() async                                       // one pass over due items; outcomes land in snapshots
}
public enum JobMerge { public static func merge(local: [Job], server: [Job]) -> [Job] }
public struct LoadJobs { init(repository:); func snapshots() -> AsyncStream<JobsSnapshot>; func refresh() async throws; func photo(jobID: String) async throws -> Data? }
public struct AttachPhoto { init(repository:); func callAsFunction(jobID: String, jpeg: Data) async throws }
public struct SaveNote { init(repository:); func callAsFunction(jobID: String, note: String) async throws }
public struct CompleteJob { init(repository:, now: @escaping @Sendable () -> Date = Date.init); func callAsFunction(jobID: String) async throws }
public struct SendPendingWork { init(repository:); func callAsFunction() async }
```

**The merge rule** (`JobMerge.merge`):
- The result follows the server's order.
- **Job missing locally:** use the server job.
- **Local job completed, with `sync` `.waiting` or `.couldNotSend`:** keep the local job.
- **Local job to do, server job not completed:** take the server's fields, but keep the local `photo` and `note` (the draft).
- **Anything else:** use the server job.
- **Local jobs the server didn't return** are appended in their local order when they're `.waiting` or `.couldNotSend`, and dropped otherwise.

struct OutboxItem: Equatable, Sendable {
    enum Kind: Equatable, Sendable { case complete(idempotencyKey: String, body: Data), photo }
    let id: UUID; let jobID: String; let kind: Kind; let sequence: Int64
    var attempts: Int; var nextAttemptAt: Date?; var photoMismatches: Int
}
final class JobStore: @unchecked Sendable {             // wraps NSPersistentContainer; all work inside context.perform
    init(storeURL: URL?) throws                          // nil → in-memory (URL(fileURLWithPath: "/dev/null"))
    func jobs() async throws -> [Job]                    // in the stored (server) order; sync derived as below
    func apply(server: [Job]) async throws               // JobMerge.merge(local:server:), then write
    func savePhoto(jobID: String, jpeg: Data) async throws        // stores bytes, count, SHA-256 hex; JobError.photoAlreadyTaken if one exists
    func saveNote(jobID: String, note: String?) async throws      // JobError.alreadyCompleted after Complete
    func photoData(jobID: String) async throws -> Data?
    func complete(jobID: String, completedAt: Date, idempotencyKey: String) async throws
    func dueItems(now: Date) async throws -> [OutboxItem]  // not failed, nextAttemptAt nil or ≤ now, by sequence
    func earliestWait() async throws -> Date?
    func finish(_ item: OutboxItem, serverJob: Job?) async throws // delete item; if serverJob, store its fields
    func reschedule(_ item: OutboxItem, at: Date, isBackoff: Bool) async throws  // attempts += 1, nextAttemptAt = at, waitIsBackoff = isBackoff
    func clearBackoffWaits() async throws                         // nextAttemptAt = nil where waitIsBackoff
    func markCouldNotSend(_ item: OutboxItem) async throws
    func recordPhotoMismatch(_ item: OutboxItem) async throws -> Int   // returns the new count
    var changes: AsyncStream<Void> { get }               // fires after every save
}
```

- **The model is built in code**, with no `.xcdatamodeld`:
  - `JobEntity` has these attributes:
    - `id`, unique
    - `address`, `task`, `windowStart`, `windowEnd`
    - `position` (`Int16`)
    - `completedAt` (`Date?`) and `note` (`String?`)
    - `photo` (binary, `allowsExternalBinaryDataStorage = true`)
    - `photoBytes` (`Int64`) and `photoSHA256` (`String?`)
    - `serverCompleted` (`Bool`)
  - `OutboxEntity` has these attributes:
    - `id` (`UUID`) and `jobID`
    - `kind` (`"complete"` or `"photo"`)
    - `idempotencyKey` and `body` (binary)
    - `sequence` (`Int64`)
    - `attempts`, `nextAttemptAt`, `waitIsBackoff` (`Bool`), `failed` (`Bool`) and `photoMismatches`
- **How `sync` is derived:**
  - `completedAt == nil` → `.notCompleted`
  - any failed outbox item for the job → `.couldNotSend`
  - any other outbox item for the job → `.waiting`
  - otherwise → `.sent`

**Files:**
- Create: `Sources/Data/Sync/{Outbox,NetworkMonitor}.swift`, `Sources/Data/LiveJobRepository.swift`
- Create: `Tests/DataTests/{FakeAPI,OutboxTests,LiveJobRepositoryTests}.swift`

**Interfaces:**
- Consumes:
  - `JobRepository` and `JobsSnapshot` from Task 1
  - `APIClienting`, `APIClient`, `APIConfig`, `sendDecision(for:)`, `JobDTO.toDomain()` and `InstallID` from Task 2
  - `JobStore` and `OutboxItem` from Task 3
- Produces:

```swift
actor Outbox {
    init(store: JobStore, api: any APIClienting, now: @escaping @Sendable () -> Date,
         sleep: @escaping @Sendable (TimeInterval) async throws -> Void, jitter: @escaping @Sendable () -> Double)
    func drain() async                 // one pass; concurrent callers wait for the running pass, then it runs once more if asked
    var sendingBlocked: Bool { get }
    func block()                       // a refresh got 401 or .missingKey
    func unblock()                     // called by LiveJobRepository.sendPending()
}
enum NetworkMonitor { static func paths() -> AsyncStream<Bool> }   // NWPathMonitor, .satisfied → true
public final class LiveJobRepository: JobRepository {
    public static func make(host: String, apiKey: String, defaults: UserDefaults = .standard, storeURL: URL) throws -> LiveJobRepository
    init(store: JobStore, api: any APIClienting, outbox: Outbox, network: AsyncStream<Bool>, defaults: UserDefaults, now: …)
}
```

**What one `drain()` pass does, item by item, in `sequence` order:**
- **Stops immediately** if `sendingBlocked`, or while the 429 pause runs.
- **A completion** goes through `api.complete`. On success it calls `store.finish(item, serverJob: dto.toDomain())`.
- **A photo** goes through `api.uploadPhoto`.
  - If the bytes and SHA-256 match the stored photo, it calls `finish(item, serverJob: nil)`.
  - If not, it calls `recordPhotoMismatch`, which returns a count. At 3 the photo is marked couldn't send; below 3 it's rescheduled with backoff.
- **A failure** follows `sendDecision`:
  - `.retryWithBackoff` → `reschedule(at: now + min(2·2^(attempts), 300)·jitter(), isBackoff: true)`. Here `attempts` is the count before this failure, so the first retry waits 2 seconds.
  - `.retryAfter(s)` → `reschedule(at: now + s, isBackoff: false)`.
  - `.pauseAllWrites(s)` → pauses until `now + s` and stops the pass.
  - `.stopAll` → `sendingBlocked = true` and stops the pass.
  - `.couldNotSend` → `markCouldNotSend`, and the pass continues.
- **After the pass,** if `store.earliestWait()` is set, it starts one `Task` that sleeps until then and drains again. Any earlier wake-up Task is cancelled first.

**What `LiveJobRepository` does:**
- **`snapshots()`:**
  - yields `JobsSnapshot(jobs: store.jobs(), updatedAt: defaults "lastRefreshAt", isOnline: latest network value (initially true), sendingBlocked: outbox.sendingBlocked)`
  - then yields again after every `store.changes`, network change and block change
- **`refresh()`:**
  - calls `api.listJobs()`, then `store.apply(server: dtos.map { $0.toDomain() })`
  - sets `"lastRefreshAt"`
  - rethrows failures, and the list stays as it was
  - a failure whose `sendDecision` is `.stopAll` (401 or `.missingKey`) also calls `outbox.block()`
- **`complete(jobID:completedAt:)`:** calls `store.complete(jobID:completedAt:idempotencyKey: UUID().uuidString)`.
- **`sendPending()`:** calls `outbox.unblock()`, then `await outbox.drain()`.
- **When the network goes from offline to online:**
  - calls `store.clearBackoffWaits()`
  - then `try? await refresh()`
  - then `await outbox.drain()`
- **After a drain that leaves the queue empty** and sent at least one item, it refreshes.
- **`make(...)`:** builds the `APIConfig` from `InstallID.current(in:)`, a `URLSession(configuration: .ephemeral)` and a `JobStore` at `storeURL`.
